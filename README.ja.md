# 灯る作法（Threshold Skills）

**作法は並べない。灯らせる。**

AI に持たせる手順（作法）を何十枚抱えても、**一覧さえプロンプトに入れない**ためのやり方です。
作法は会話と同じ記憶の中に置きます。目の前の問いが十分近い時だけ作法が浮かび、その時も返すのは題名と読みに行くための問い合わせだけです。

---

## 困っていたこと

手順は溜まっていきます。動画の出し方、報告の確かめ方、絶対に触ってはいけない物。よくあるやり方には、それぞれ代価があります。

| やり方 | 代価 |
|---|---|
| **全部をシステムプロンプトに書く** | 関係の無い手順まで、毎回のやり取りで払う。 |
| **段階的に開く（名前と説明の一覧を置き、本文は要る時に読む）** | ずっと良い。ただ一覧そのものは毎回の会話の頭に読み込まれ、作法が増えるほど伸びる。（[agentskills.io](https://agentskills.io/client-implementation)） |
| **検索結果に作法を同梱する** | 試した。検索のたびに作法の本文が付いてきて、削ったトークンが戻ってきた。 |

## 仕組み

1. **作法も結晶** — 作法は会話の結晶と同じ形で、節に分けて置きます。最初の節には「いつ着るか」を書きます。
2. **順位ではなく閾値** — 問いを作法の層まるごとと比べ、**0.80** に届かなければ何も返しません。だから「返ってきたこと」自体が、近い作法があるという合図になります。
3. **返すのは題名だけ** — 返るのは作法の題名と、その節を読むための問い合わせです。本文は AI が降りると決めた時だけ読みます。
4. **撃つのは手を動かす直前** — 作る・直す・決める一歩手前で引きます。過去を読んでいる最中ではありません。**読むことと着ることは別。**
5. **1つの会話で1回** — 同じ会話で同じ作法がもう一度灯ったら、題名だけを出します。

## 一覧方式との比べ

| | 一覧 ＋ 要る時に本文 | 灯る作法 |
|---|---|---|
| 会話の頭に読み込む物 | すべての作法の名前と説明 | 何も無い |
| 作法が増えると伸びるか | 伸びる | 伸びない |
| どう選ぶか | モデルが一覧を読んで決める | 問いとの近さが決まった閾値を超えるか |
| 当てはまる作法が無い時 | 一覧は文脈に残る | 何も返らない |
| 「いつ使うか」の置き場 | 説明の1行 | 作法の最初の節（降りた時だけ読む） |

一覧は読みやすく、作法が数枚なら十分に働きます。灯る作法は、手順が溜まり続けてもプロンプトは増やしたくない時のためのものです。
